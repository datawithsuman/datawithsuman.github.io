A/B testing

14 questions on A/B testing, from 16 lessons. Pick an answer in your head, then open it.

On the roadmap for: ML Engineering, Data Science.

  1. Question 1 of 14

    Why do we randomly assign users to A and B?

    1. A. To save money
    2. B. So the only systematic difference between the groups is the change, and other causes balance out
    3. C. To make the groups smaller
    4. D. Randomisation isn't needed
    View answer

    ✓ B. So the only systematic difference between the groups is the change, and other causes balance out

    Without randomisation, who gets the feature can be linked to the outcome, and the comparison stops being causal.

    Lesson: Randomisation and Assignment

  2. Question 2 of 14

    What is a guardrail metric?

    1. A. The metric you're trying to improve
    2. B. A metric that must not get worse, such as latency, crashes or unsubscribes, even if the main metric wins
    3. C. The number of users
    4. D. A metric you check after launch only
    View answer

    ✓ B. A metric that must not get worse, such as latency, crashes or unsubscribes, even if the main metric wins

    Guardrails stop you shipping a win on one metric that quietly harms the business or users elsewhere.

    Lesson: Choosing Metrics: OEC, Drivers and Guardrails

  3. Question 3 of 14

    You want to detect an effect half as large as before, with the same power. How does the required sample size change?

    1. A. It halves
    2. B. It doubles
    3. C. It roughly quadruples
    4. D. It stays the same
    View answer

    ✓ C. It roughly quadruples

    Sample size scales with 1 / (effect)². Halving the effect you want to detect needs about 4× the users.

    Lesson: Sample Size, Power and Runtime

  4. Question 4 of 14

    Your test is statistically significant. What else should you check before shipping?

    1. A. Nothing
    2. B. Whether the effect is big enough to matter (the confidence interval vs the smallest worthwhile change), plus guardrails
    3. C. Only the p-value
    4. D. Whether the test ran on Monday
    View answer

    ✓ B. Whether the effect is big enough to matter (the confidence interval vs the smallest worthwhile change), plus guardrails

    Significant isn't the same as worthwhile; decide using the interval and the costs.

    Lesson: Reading the Result: Significance and Decisions

  5. Question 5 of 14

    You randomise by user but measure click-through rate per page view. What goes wrong?

    1. A. Nothing
    2. B. Page views from the same user are correlated, so treating them as independent understates the variance; use the delta method or user-level analysis
    3. C. CTR can't be computed
    4. D. The groups become unbalanced
    View answer

    ✓ B. Page views from the same user are correlated, so treating them as independent understates the variance; use the delta method or user-level analysis

    The analysis unit must respect the randomisation unit, or p-values come out too small.

    Lesson: Ratio Metrics and the Delta Method

  6. Question 6 of 14

    How does CUPED shorten an A/B test?

    1. A. By peeking early
    2. B. By using each user's pre-experiment behaviour to remove predictable variation from the metric
    3. C. By dropping users
    4. D. By lowering the significance level
    View answer

    ✓ B. By using each user's pre-experiment behaviour to remove predictable variation from the metric

    Less variance means the same precision with fewer users, without biasing the estimate.

    Lesson: Variance Reduction with CUPED

  7. Question 7 of 14

    Revenue per user is your main metric, and a few huge spenders swing every result. What's a common fix?

    1. A. Drop the test
    2. B. Cap (winsorise) extreme values or analyse a transformed metric, and check with a bootstrap
    3. C. Only count small spenders
    4. D. Use the median of the treatment group only
    View answer

    ✓ B. Cap (winsorise) extreme values or analyse a transformed metric, and check with a bootstrap

    Heavy tails inflate variance; capping trades a little bias for much more stable results.

    Lesson: Revenue and Heavy-Tailed Metrics

  8. Question 8 of 14

    Your manager wants to check the test daily and stop as soon as it wins. How can that be valid?

    1. A. It can't
    2. B. Use a sequential testing method designed for repeated looks, such as always-valid p-values or alpha spending
    3. C. Check only at noon
    4. D. Use a lower p-value threshold once
    View answer

    ✓ B. Use a sequential testing method designed for repeated looks, such as always-valid p-values or alpha spending

    Ordinary p-values assume one look; sequential methods keep the false-positive rate at 5% across looks.

    Lesson: Peeking and Sequential Testing

  9. Question 9 of 14

    You tested 20 metrics and one came back significant at p < 0.05. Is it a real win?

    1. A. Yes, definitely
    2. B. Not necessarily: with 20 tests, about one false positive is expected by chance; correct for multiple testing
    3. C. Only if it's revenue
    4. D. Yes, if the p-value is 0.049
    View answer

    ✓ B. Not necessarily: with 20 tests, about one false positive is expected by chance; correct for multiple testing

    Use Bonferroni or Benjamini–Hochberg, or treat the result as a hypothesis for a new test.

    Lesson: Multiple Testing and Segments

  10. Question 10 of 14

    You planned a 50/50 split but got 50,500 vs 49,500 users out of 100,000. Does it matter?

    1. A. No, it's close enough
    2. B. Yes: a chi-squared test gives p ≈ 0.002, a sample ratio mismatch that points to a bug in assignment or logging
    3. C. Only if revenue differs
    4. D. Only for small tests
    View answer

    ✓ B. Yes: a chi-squared test gives p ≈ 0.002, a sample ratio mismatch that points to a bug in assignment or logging

    χ² = 500²/50,000 × 2 = 10. Investigate before trusting any result.

    Lesson: Trust Checks: SRM and A/A Tests

  11. Question 11 of 14

    A new feature lifted engagement by 5% in week one. Why might it not last?

    1. A. It always lasts
    2. B. Novelty: users try new things at first, and the effect can fade, so look at the trend over time or at new users
    3. C. Week one is always wrong
    4. D. Engagement can't change
    View answer

    ✓ B. Novelty: users try new things at first, and the effect can fade, so look at the trend over time or at new users

    Primacy effects run the other way: users resist change at first. Longer tests reveal the true long-term effect.

    Lesson: Novelty, Primacy and Long-Term Effects

  12. Question 12 of 14

    A ride-app test showed treated riders booking 10% more, but after launch bookings barely moved. Why?

    1. A. The test was too short
    2. B. Interference: treated riders took drivers that control riders would have used, so the test overstated the total effect
    3. C. Riders lied
    4. D. The launch had a bug
    View answer

    ✓ B. Interference: treated riders took drivers that control riders would have used, so the test overstated the total effect

    In shared markets, randomise by region or time slot (switchbacks) so the groups don't compete.

    Lesson: Interference: When Groups Affect Each Other

  13. Question 13 of 14

    When should you prefer a classic A/B test over a multi-armed bandit?

    1. A. Never
    2. B. When you need a clean, unbiased estimate of the effect to make a lasting decision
    3. C. When you want the most clicks during the test
    4. D. When there are many variants
    View answer

    ✓ B. When you need a clean, unbiased estimate of the effect to make a lasting decision

    Bandits reduce the cost of showing worse options but give less reliable effect estimates.

    Lesson: Bandits vs A/B Tests

  14. Question 14 of 14

    Your coupon test is flat overall. Could the coupon still be worth giving to some users?

    1. A. No
    2. B. Yes: uplift modelling estimates who responds, so you can target people the coupon actually changes
    3. C. Only if you rerun the same test
    4. D. Only for new users
    View answer

    ✓ B. Yes: uplift modelling estimates who responds, so you can target people the coupon actually changes

    Average effects can hide positive and negative groups; validate any targeting rule in a new test.

    Lesson: Heterogeneous Effects and Uplift Modelling

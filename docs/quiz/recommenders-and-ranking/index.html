Recommenders and ranking

  1. Question 1 of 8

    How does a recommender pick a few items for a user from millions?

    1. A. Show the most popular items to everyone
    2. B. Score every item in the catalogue with the full model
    3. C. In stages: fast retrieval to hundreds, then a heavier ranker
    4. D. Pick items at random, then learn from clicks
    View answer

    ✓ C. In stages: fast retrieval to hundreds, then a heavier ranker

    Scoring millions of items with a big model per request is too slow; retrieval then ranking keeps it fast.

    Lesson: Design a recommendation system

  2. Question 2 of 8

    Why can interleaving compare two rankers with far fewer users than an A/B test?

    1. A. It uses only offline data, so no live users are needed
    2. B. It skips significance testing to save time
    3. C. It tests one ranker at a time on all of the users
    4. D. Each user sees both rankers mixed; clicks pick a winner
    View answer

    ✓ D. Each user sees both rankers mixed; clicks pick a winner

    Comparing within the same user removes between-user noise, so a preference shows up much sooner.

    Lesson: Test Rankers Faster with Interleaving

  3. Question 3 of 8

    You want to learn which image to show each user for each title. Why use a bandit rather than a fixed A/B test?

    1. A. Bandits need no data to start choosing well
    2. B. It shifts traffic to better images while learning
    3. C. Bandits are always unbiased, unlike A/B tests
    4. D. A/B tests can't compare more than two images
    View answer

    ✓ B. It shifts traffic to better images while learning

    Keep a holdout or a proper test alongside it to prove the personalisation actually helps.

    Lesson: Personalise Images with Bandits

  4. Question 4 of 8

    Why keep the keyword index when adding embedding-based product search?

    1. A. Embeddings blur exact tokens like model numbers; keywords keep filters
    2. B. Keeping both saves storage compared with embeddings alone
    3. C. Keyword search is always more relevant than embeddings
    4. D. Embeddings are too slow to search at this scale
    View answer

    ✓ A. Embeddings blur exact tokens like model numbers; keywords keep filters

    Hybrid retrieval runs both and lets the re-ranker combine them; embeddings help most on long-tail queries.

    Lesson: Design Semantic Product Search

  5. Question 5 of 8

    In a feed ranker, why combine several predicted actions in a value model instead of ranking by click probability?

    1. A. Clicks reward regretted clickbait; weighting actions fixes it
    2. B. It's faster to compute than a single click prediction
    3. C. Click probability can't be predicted for brand-new posts
    4. D. Value models don't need any training data to work
    View answer

    ✓ A. Clicks reward regretted clickbait; weighting actions fixes it

    Multi-task predictions plus tunable weights let the product balance engagement types without retraining.

    Lesson: Design Feed Ranking

  6. Question 6 of 8

    You train a click model keeping only 2.5% of non-click examples. What must you do before using its predictions in the auction?

    1. A. Multiply every prediction by 40
    2. B. Recalibrate with q = p / (p + (1 − p) / w)
    3. C. Nothing; the probabilities are already correct
    4. D. Retrain the model on all the data
    View answer

    ✓ B. Recalibrate with q = p / (p + (1 − p) / w)

    Downsampling inflates predicted probabilities; the auction needs real click rates, so convert them back.

    Lesson: Design Ad Click Prediction

  7. Question 7 of 8

    A marketplace adds an embedding per listing to its ranking network. Training NDCG jumps, test NDCG doesn't. Why?

    1. A. The embedding is too small to hold enough detail
    2. B. Few bookings per listing, so its embedding memorises noise
    3. C. Embeddings never work for ranking problems
    4. D. The test set must contain different listings
    View answer

    ✓ B. Few bookings per listing, so its embedding memorises noise

    Item embeddings need many interactions per item, as with videos or words; scarce bookings make them overfit.

    Lesson: Design Search Ranking with Deep Learning

  8. Question 8 of 8

    Why does a notification bandit penalise templates a user saw recently?

    1. A. To keep the decision logs small and cheap
    2. B. To save money on sending each notification
    3. C. Templates expire after a few days of use
    4. D. Fresh messages work better; repeats get tuned out
    View answer

    ✓ D. Fresh messages work better; repeats get tuned out

    A recency penalty with a half-life, plus softmax exploration, keeps messages varied while still favouring strong templates.

    Lesson: Design Notification Optimisation

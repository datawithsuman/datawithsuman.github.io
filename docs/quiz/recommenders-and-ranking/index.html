  1. Question 1 of 8

    How does a recommender pick a few items for a user from millions?

    1. A. Score every item with the full model
    2. B. In stages: fast candidate retrieval narrows to hundreds, then a heavier ranking model orders them
    3. C. Pick at random
    4. D. Show the most popular items only
    View answer

    ✓ B. In stages: fast candidate retrieval narrows to hundreds, then a heavier ranking model orders them

    Scoring millions of items with a big model per request is too slow; retrieval then ranking keeps it fast.

    Lesson: Design a recommendation system

  2. Question 2 of 8

    Why can interleaving compare two rankers with far fewer users than an A/B test?

    1. A. It uses offline data only
    2. B. Each user sees one list mixing both rankers' results, and their clicks show directly which ranker they prefer
    3. C. It skips statistics
    4. D. It tests one ranker at a time
    View answer

    ✓ B. Each user sees one list mixing both rankers' results, and their clicks show directly which ranker they prefer

    Comparing within the same user removes between-user noise, so a preference shows up much sooner.

    Lesson: Test Rankers Faster with Interleaving

  3. Question 3 of 8

    You want to learn which image to show each user for each title. Why use a bandit rather than a fixed A/B test?

    1. A. Bandits need no data
    2. B. A bandit shifts traffic towards better images while it learns, balancing exploration and exploitation
    3. C. A/B tests can't compare images
    4. D. Bandits are always unbiased
    View answer

    ✓ B. A bandit shifts traffic towards better images while it learns, balancing exploration and exploitation

    Keep a holdout or a proper test alongside it to prove the personalisation actually helps.

    Lesson: Personalise Images with Bandits

  4. Question 4 of 8

    Why keep the keyword index when adding embedding-based product search?

    1. A. Embeddings are too slow
    2. B. Embeddings blur rare exact tokens like model numbers, and the keyword index already supports filters and facets
    3. C. Keyword search is always more relevant
    4. D. To save storage
    View answer

    ✓ B. Embeddings blur rare exact tokens like model numbers, and the keyword index already supports filters and facets

    Hybrid retrieval runs both and lets the re-ranker combine them; embeddings help most on long-tail queries.

    Lesson: Design Semantic Product Search

  5. Question 5 of 8

    In a feed ranker, why combine several predicted actions in a value model instead of ranking by click probability?

    1. A. It's faster
    2. B. Clicks reward clickbait people regret; weighting likes and shares and subtracting 'see less' ranks by what people value
    3. C. Click probability can't be predicted
    4. D. Value models need no data
    View answer

    ✓ B. Clicks reward clickbait people regret; weighting likes and shares and subtracting 'see less' ranks by what people value

    Multi-task predictions plus tunable weights let the product balance engagement types without retraining.

    Lesson: Design Feed Ranking

  6. Question 6 of 8

    You train a click model keeping only 2.5% of non-click examples. What must you do before using its predictions in the auction?

    1. A. Nothing
    2. B. Recalibrate: q = p / (p + (1 − p) / w), because the model saw far more clicks than reality
    3. C. Multiply every prediction by 40
    4. D. Retrain on all data
    View answer

    ✓ B. Recalibrate: q = p / (p + (1 − p) / w), because the model saw far more clicks than reality

    Downsampling inflates predicted probabilities; the auction needs real click rates, so convert them back.

    Lesson: Design Ad Click Prediction

  7. Question 7 of 8

    A marketplace adds an embedding per listing to its ranking network. Training NDCG jumps, test NDCG doesn't. Why?

    1. A. The embedding is too small
    2. B. Each listing has few bookings, so its embedding memorises noise and overfits
    3. C. Embeddings never work
    4. D. The test set is wrong
    View answer

    ✓ B. Each listing has few bookings, so its embedding memorises noise and overfits

    Item embeddings need many interactions per item, as with videos or words; scarce bookings make them overfit.

    Lesson: Design Search Ranking with Deep Learning

  8. Question 8 of 8

    Why does a notification bandit penalise templates a user saw recently?

    1. A. To save money
    2. B. Fresh messages work better; repeating even the best one makes users tune it out, so the penalty fades over days
    3. C. Templates expire
    4. D. To reduce logging
    View answer

    ✓ B. Fresh messages work better; repeating even the best one makes users tune it out, so the penalty fades over days

    A recency penalty with a half-life, plus softmax exploration, keeps messages varied while still favouring strong templates.

    Lesson: Design Notification Optimisation

RAG

12 questions on RAG, from 13 lessons. Pick an answer in your head, then open it.

On the roadmap for: AI Engineering, ML Engineering.

  1. Question 1 of 12

    What are the basic steps of a RAG system?

    1. A. Fine-tune the model on every document
    2. B. Split documents into chunks, embed and index them, retrieve the most relevant chunks for a question, and give them to the LLM to answer from
    3. C. Ask the LLM to remember the documents
    4. D. Search the web for every question
    View answer

    ✓ B. Split documents into chunks, embed and index them, retrieve the most relevant chunks for a question, and give them to the LLM to answer from

    RAG keeps knowledge outside the model and fetches it at question time, so it can be updated without retraining.

    Lesson: RAG End to End

  2. Question 2 of 12

    Chunks that are too large cause one problem; chunks that are too small cause another. Which pair is right?

    1. A. Large: too fast; small: too slow
    2. B. Large: the relevant sentence is diluted and wastes context; small: the answer gets split and loses its surrounding meaning
    3. C. Large: more accurate; small: never retrieved
    4. D. Size doesn't matter
    View answer

    ✓ B. Large: the relevant sentence is diluted and wastes context; small: the answer gets split and loses its surrounding meaning

    Chunk size is a trade-off between precise retrieval and enough context to answer; overlap and structure-aware splitting help.

    Lesson: Parsing and Chunking

  3. Question 3 of 12

    Your RAG system misreads tables in PDFs. Where should you fix it first?

    1. A. Use a bigger LLM
    2. B. In parsing: extract tables with their structure (rows, headers) before chunking
    3. C. Raise the temperature
    4. D. Add more chunks per question
    View answer

    ✓ B. In parsing: extract tables with their structure (rows, headers) before chunking

    If parsing flattens a table into jumbled text, no retriever or model can recover it. Garbage in, garbage out.

    Lesson: Parsing and Chunking

  4. Question 4 of 12

    Approximate nearest-neighbour indexes such as HNSW trade what for speed?

    1. A. Nothing
    2. B. A small loss in recall: they may miss some true nearest neighbours
    3. C. They need labelled data
    4. D. They only work on text
    View answer

    ✓ B. A small loss in recall: they may miss some true nearest neighbours

    Exact search over millions of vectors is too slow, so ANN indexes search a graph or clusters and accept slightly imperfect recall.

    Lesson: Embeddings and Vector Indexes

  5. Question 5 of 12

    Why does pure dense (embedding) search often miss queries with exact product codes or names?

    1. A. Embeddings can't store numbers
    2. B. Embeddings capture meaning, so rare exact tokens get blurred; keyword search (BM25) matches them exactly
    3. C. BM25 is always better
    4. D. Names are removed by tokenisers
    View answer

    ✓ B. Embeddings capture meaning, so rare exact tokens get blurred; keyword search (BM25) matches them exactly

    Hybrid search combines both and merges the lists, for example with reciprocal rank fusion.

    Lesson: Advanced RAG: Hybrid Search, Re-ranking, Query Rewriting and GraphRAG

  6. Question 6 of 12

    The right chunk is retrieved but ranked 12th, and you pass the top 5 to the LLM. What's the usual fix?

    1. A. Pass all 100 chunks
    2. B. Add a re-ranker (e.g. a cross-encoder) that rescores the top candidates more carefully
    3. C. Lower the temperature
    4. D. Shorten the question
    View answer

    ✓ B. Add a re-ranker (e.g. a cross-encoder) that rescores the top candidates more carefully

    Retrieve wide and cheap, then re-rank a short list with a slower, more accurate model.

    Lesson: Re-ranking and Late Interaction

  7. Question 7 of 12

    What is 'late interaction', as in ColBERT?

    1. A. Calling the LLM after the user leaves
    2. B. Keeping one embedding per token and scoring query–document pairs by matching token vectors (MaxSim)
    3. C. Re-ranking with a second LLM
    4. D. Delaying indexing until night
    View answer

    ✓ B. Keeping one embedding per token and scoring query–document pairs by matching token vectors (MaxSim)

    It sits between a single-vector bi-encoder (fast, coarse) and a cross-encoder (slow, precise).

    Lesson: Re-ranking and Late Interaction

  8. Question 8 of 12

    The correct chunk was retrieved, but the answer is still wrong. Which is a likely cause?

    1. A. The vector index is down
    2. B. The model ignored or misread the chunk, for example because it sat among many others or conflicted with another source
    3. C. The embedding model is too small
    4. D. The question was too short
    View answer

    ✓ B. The model ignored or misread the chunk, for example because it sat among many others or conflicted with another source

    Retrieval isn't the whole story: ask for answers grounded in quoted sources, handle conflicts, and allow 'I don't know'.

    Lesson: Grounded Answers: Citations, Conflicts and Saying No

  9. Question 9 of 12

    When might you skip building a vector index altogether?

    1. A. Never
    2. B. When the knowledge is small enough to fit in the context window, or can be fetched exactly with a tool or database query
    3. C. When users ask many questions
    4. D. When documents change daily
    View answer

    ✓ B. When the knowledge is small enough to fit in the context window, or can be fetched exactly with a tool or database query

    Long context, structured queries or an agent with search tools can beat a vector index for small or structured data.

    Lesson: Agentic RAG, and When Not to Index

  10. Question 10 of 12

    How should a RAG system stop users from retrieving documents they're not allowed to see?

    1. A. Tell the LLM not to reveal them
    2. B. Store permissions with each chunk and filter by the user's access at retrieval time
    3. C. Hide them in a separate index nobody knows about
    4. D. Remove sensitive words
    View answer

    ✓ B. Store permissions with each chunk and filter by the user's access at retrieval time

    Instructions can be ignored or bypassed; access filtering must happen before the model sees anything.

    Lesson: Permissions and Poisoning in RAG

  11. Question 11 of 12

    A better embedding model comes out. What must you do to use it?

    1. A. Nothing, old vectors still work
    2. B. Re-embed the whole corpus, because vectors from different models aren't comparable
    3. C. Embed only new documents
    4. D. Change the chunk size
    View answer

    ✓ B. Re-embed the whole corpus, because vectors from different models aren't comparable

    Each model has its own vector space. Plan a background re-index and switch over once it's complete and evaluated.

    Lesson: Keeping an Index Current

  12. Question 12 of 12

    Your RAG chatbot gave a confident wrong answer. What should you check first?

    1. A. The model's size
    2. B. The trace: was the right content retrieved, and if so, did the answer actually use it?
    3. C. The UI colours
    4. D. The number of users
    View answer

    ✓ B. The trace: was the right content retrieved, and if so, did the answer actually use it?

    Separating retrieval failures from generation failures tells you which half of the system to fix.

    Lesson: RAG: Wrong Answer, Where to Look First

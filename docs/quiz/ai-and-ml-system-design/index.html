AI and ML system design

20 questions on AI and ML system design, from 18 lessons. Pick an answer in your head, then open it.

  1. Question 1 of 20

    A support chatbot answers from help articles. When should it hand over to a human?

    1. A. When support is weak, a person is asked for, or it's risky
    2. B. Never; a good chatbot should always attempt an answer
    3. C. Only outside working hours, when human agents are busy
    4. D. After exactly three messages, whatever the topic is
    View answer

    ✓ A. When support is weak, a person is asked for, or it's risky

    A clear escalation path keeps wrong answers from reaching users on cases the bot shouldn't handle.

    Lesson: Design a Support Chatbot

  2. Question 2 of 20

    Which pair of measurements best shows whether a support chatbot is working?

    1. A. Tokens used per chat, plus the size and speed of the model behind it
    2. B. Issues resolved without a human, plus correct escalations
    3. C. Page load time and uptime of the chat widget
    4. D. Number of messages sent per conversation
    View answer

    ✓ B. Issues resolved without a human, plus correct escalations

    Measure outcomes: did users get a correct answer, and did hard cases reach a human?

    Lesson: Design a Support Chatbot

  3. Question 3 of 20

    An assistant's tools will grow from a handful to dozens. How do you keep tool choice reliable?

    1. A. Retrieve or group only the relevant tools, with clear schemas
    2. B. Put every tool's full description in every prompt
    3. C. Let the model write brand-new tools for itself whenever it needs them
    4. D. Remove tool descriptions to save tokens
    View answer

    ✓ A. Retrieve or group only the relevant tools, with clear schemas

    Too many tools in context confuses selection and costs tokens; narrowing the set first keeps choices accurate.

    Lesson: Design a Store Assistant

  4. Question 4 of 20

    In an enterprise RAG system, where should 'who can see this document' be enforced?

    1. A. In the system prompt, by telling the model what to hide
    2. B. Nowhere: internal documents can be seen by everyone
    3. C. At retrieval time, filtering chunks by the user's permissions
    4. D. After the answer is written, by scanning it for secrets before it's shown
    View answer

    ✓ C. At retrieval time, filtering chunks by the user's permissions

    If a restricted chunk reaches the model, it can leak into the answer. Filter by access rights in the search itself.

    Lesson: Design an Enterprise RAG System

  5. Question 5 of 20

    A text-to-SQL system works over thousands of tables. What should happen before the model writes SQL?

    1. A. Find the relevant tables and columns first (schema linking)
    2. B. Load the entire database schema into every single prompt
    3. C. Nothing: the model can find the tables itself
    4. D. Ask the user to name the exact tables to use
    View answer

    ✓ A. Find the relevant tables and columns first (schema linking)

    A focused schema makes the right joins far more likely and keeps the prompt small.

    Lesson: Design a Text-to-SQL System

  6. Question 6 of 20

    How do you make a text-to-SQL system safe to run?

    1. A. Skip validation, since the model writes correct SQL
    2. B. Run SQL read-only with row and time limits, after validating it
    3. C. Give it admin rights, so its queries never fail because of missing permissions
    4. D. Let it write directly to production tables for speed
    View answer

    ✓ B. Run SQL read-only with row and time limits, after validating it

    Generated queries can be wrong or expensive; least privilege and limits contain the damage.

    Lesson: Design a Text-to-SQL System

  7. Question 7 of 20

    A refund agent can issue refunds. What is a sensible safeguard?

    1. A. Disable logging so customer data isn't stored
    2. B. Retry failed refunds automatically, again and again, until each one succeeds
    3. C. Let it refund any amount, but log every refund
    4. D. Require approval above a set amount, and make refunds idempotent
    View answer

    ✓ D. Require approval above a set amount, and make refunds idempotent

    Money-moving actions need limits, approvals and safe retries so a mistake or retry can't pay twice.

    Lesson: Design a Refund-Handling Agent

  8. Question 8 of 20

    Why would a research agent split work across parallel subagents?

    1. A. Each explores one part in its own context; a lead combines them
    2. B. To use fewer tokens overall than a single agent would need for the same task
    3. C. Because a single agent can't call a search tool
    4. D. So the final answer can be skipped if time runs out
    View answer

    ✓ A. Each explores one part in its own context; a lead combines them

    Parallel, focused contexts cover broad questions faster, at the cost of more total tokens.

    Lesson: Design a Research Agent

  9. Question 9 of 20

    Code autocomplete must respond in under 200 ms at huge scale. Which choice helps most?

    1. A. Waiting until the user stops typing for 5 seconds before sending any request
    2. B. A small, fast model, plus caching and cancelling stale requests
    3. C. The largest available model, for the best suggestions
    4. D. Sending the whole repository with every request
    View answer

    ✓ B. A small, fast model, plus caching and cancelling stale requests

    Latency is the product here; small models, reuse of context and dropping outdated requests keep it fast.

    Lesson: Design Code Autocomplete

  10. Question 10 of 20

    Many teams share LLMs from several vendors, and customer data mustn't leak. What is the core piece of the platform?

    1. A. A single in-house model that every team is required to use
    2. B. A central gateway for access, redaction, routing and logs
    3. C. Each team calls vendors directly with its own API keys
    4. D. One shared API key kept in a team document for everyone
    View answer

    ✓ B. A central gateway for access, redaction, routing and logs

    One gateway applies the same safety, cost and audit rules to every call, whichever vendor serves it.

    Lesson: Design a Shared LLM Platform

  11. Question 11 of 20

    For a voice AI agent on a support line, which metric best captures how responsive it feels?

    1. A. Number of tools the agent can call while talking
    2. B. Words per minute the agent speaks during the call, measured end to end
    3. C. Time from the caller finishing to the first useful words
    4. D. Total call length from the first ring to hang-up
    View answer

    ✓ C. Time from the caller finishing to the first useful words

    Filler like 'uh-huh' hides silence without helping; measure the first relevant response, and cut real waits with parallel work and streaming.

    Lesson: Design a Voice AI Agent

  12. Question 12 of 20

    An evaluation gate runs 150 questions on every pull request. What is it good at catching?

    1. A. Every regression, however small it is, before any change is merged
    2. B. Only latency regressions, not quality changes
    3. C. Nothing useful, because 150 questions is too few
    4. D. Large regressions quickly; small ones need a bigger set
    View answer

    ✓ D. Large regressions quickly; small ones need a bigger set

    A small set has little statistical power, which is why gates are layered: a fast PR set, a larger release set, and live sampling.

    Lesson: Design an LLM Evaluation Platform

  13. Question 13 of 20

    An invoice extractor is 99% confident about a total that is wrong. What should catch it?

    1. A. A bigger model that is more confident
    2. B. Rule checks that don't use the model: totals add up, PO matches
    3. C. Nothing; 99% confidence is reliable enough for payments of any size
    4. D. Running the same model again and comparing
    View answer

    ✓ B. Rule checks that don't use the model: totals add up, PO matches

    Models can be confidently wrong; independent checks on money fields catch what confidence misses.

    Lesson: Design a Document Extraction Pipeline

  14. Question 14 of 20

    For a coding agent that opens pull requests, which failure is the most serious?

    1. A. The agent fails to open a pull request at all
    2. B. The pull request passes CI but makes the wrong change
    3. C. The pull request has an unusually long description
    4. D. The pull request fails the CI checks
    View answer

    ✓ B. The pull request passes CI but makes the wrong change

    A wrong change that passes CI can merge unnoticed and erodes trust in the whole system; verifiers and a scope-checking judge reduce it.

    Lesson: Design a Background Coding Agent

  15. Question 15 of 20

    Why do large platforms moderate chat with many small classifiers instead of one big LLM per message?

    1. A. Small classifiers are always more accurate than LLMs
    2. B. A big LLM is too slow and costly at that volume
    3. C. LLMs can't understand short, informal chat messages
    4. D. Regulations forbid using LLMs to moderate user chat
    View answer

    ✓ B. A big LLM is too slow and costly at that volume

    Distilled, quantized specialist models carry the volume; context-aware LLMs and people handle the hard cases.

    Lesson: Design AI Content Moderation

  16. Question 16 of 20

    An AI tutor's users rate it highly. Why isn't that enough to show it works?

    1. A. Ratings from students are usually fake or random, so they can be ignored
    2. B. Ratings can't legally be collected from children
    3. C. Only teachers' ratings count, not students' ratings
    4. D. They may like being given answers; check the next problem
    View answer

    ✓ D. They may like being given answers; check the next problem

    Measure learning, such as next-item correctness without help, and track answers given away as a guardrail.

    Lesson: Design an AI Tutor

  17. Question 17 of 20

    LoRA fine-tuning made a small vision model accurate on Indonesian IDs but not on Thai. What's the likely fix?

    1. A. Use a longer prompt that includes Thai examples
    2. B. Fully train the vision parts on Thai text images
    3. C. Train the LoRA adapter for many more epochs
    4. D. Lower the image resolution so the text is clearer
    View answer

    ✓ B. Fully train the vision parts on Thai text images

    If the vision encoder has rarely seen a script, small adapters can't teach it to read; it needs full training on that script.

    Lesson: Design a Custom Vision LLM

  18. Question 18 of 20

    Fraud is about 1 in 1,000 payments. Why is '99.9% accuracy' a poor way to describe a fraud model?

    1. A. Accuracy can't be computed on payment data
    2. B. It's too low; a fraud model should reach 99.99%
    3. C. Approving every payment also scores 99.9%
    4. D. Fraud models always hit 100% on training data
    View answer

    ✓ C. Approving every payment also scores 99.9%

    With rare positives, accuracy hides the trade-off; set thresholds from the cost of each mistake and use verification for the uncertain middle.

    Lesson: Design Real-Time Fraud Detection

  19. Question 19 of 20

    Why do many ETA systems keep the routing engine and train ML to predict its error?

    1. A. It removes the need for live traffic data
    2. B. ML can't predict times on its own
    3. C. Routing engines are always wrong, so ML has to replace them completely
    4. D. Routing captures roads and traffic; learning its error is easier
    View answer

    ✓ D. Routing captures roads and traffic; learning its error is easier

    The model learns what routing misses, like pickup delays, and an asymmetric loss can penalise lateness more.

    Lesson: Design ETA Prediction

  20. Question 20 of 20

    Why challenge medium-risk sign-ups instead of blocking them?

    1. A. Challenges are free and never annoy real people
    2. B. It costs people seconds but stops scripts; later layers catch the rest
    3. C. Medium risk means the account is almost certainly a real person, so let it in
    4. D. Blocking new users is illegal in most countries
    View answer

    ✓ B. It costs people seconds but stops scripts; later layers catch the rest

    A funnel lets each layer be less strict, because the next layer catches what it misses.

    Lesson: Design Spam and Fake Account Detection

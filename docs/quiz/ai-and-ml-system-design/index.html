AI and ML system design

20 questions on AI and ML system design, from 18 lessons. Pick an answer in your head, then open it.

On the roadmap for: AI Engineering, ML Engineering.

  1. Question 1 of 20

    A support chatbot answers from help articles. When should it hand over to a human?

    1. A. Never; it should always answer
    2. B. When it can't find good supporting articles, the user asks for a person, or the issue is sensitive or high-risk
    3. C. After exactly three messages
    4. D. Only at night
    View answer

    ✓ B. When it can't find good supporting articles, the user asks for a person, or the issue is sensitive or high-risk

    A clear escalation path keeps wrong answers from reaching users on cases the bot shouldn't handle.

    Lesson: Design a Support Chatbot

  2. Question 2 of 20

    Which pair of measurements best shows whether a support chatbot is working?

    1. A. Tokens used and model size
    2. B. Issues resolved without a human, plus correct escalations (and answer quality checks)
    3. C. Number of messages sent
    4. D. Page load time
    View answer

    ✓ B. Issues resolved without a human, plus correct escalations (and answer quality checks)

    Measure outcomes: did users get a correct answer, and did hard cases reach a human?

    Lesson: Design a Support Chatbot

  3. Question 3 of 20

    An assistant's tools will grow from a handful to dozens. How do you keep tool choice reliable?

    1. A. Put every tool in every prompt
    2. B. Retrieve or group only the tools relevant to the request, with clear names and schemas
    3. C. Remove tool descriptions
    4. D. Let the model invent tools
    View answer

    ✓ B. Retrieve or group only the tools relevant to the request, with clear names and schemas

    Too many tools in context confuses selection and costs tokens; narrowing the set first keeps choices accurate.

    Lesson: Design a Store Assistant

  4. Question 4 of 20

    In an enterprise RAG system, where should 'who can see this document' be enforced?

    1. A. In the system prompt only
    2. B. At retrieval time, filtering chunks by the user's permissions before anything reaches the LLM
    3. C. After the answer is written
    4. D. Nowhere; internal data is shared
    View answer

    ✓ B. At retrieval time, filtering chunks by the user's permissions before anything reaches the LLM

    If a restricted chunk reaches the model, it can leak into the answer. Filter by access rights in the search itself.

    Lesson: Design an Enterprise RAG System

  5. Question 5 of 20

    A text-to-SQL system works over thousands of tables. What should happen before the model writes SQL?

    1. A. Nothing
    2. B. Find the relevant tables and columns first (schema linking), then give only those to the model
    3. C. Load the whole schema into the prompt
    4. D. Ask the user to write the SQL
    View answer

    ✓ B. Find the relevant tables and columns first (schema linking), then give only those to the model

    A focused schema makes the right joins far more likely and keeps the prompt small.

    Lesson: Design a Text-to-SQL System

  6. Question 6 of 20

    How do you make a text-to-SQL system safe to run?

    1. A. Give it admin rights
    2. B. Run generated SQL as read-only with row and time limits, and validate it before execution
    3. C. Let users edit the database directly
    4. D. Skip validation for speed
    View answer

    ✓ B. Run generated SQL as read-only with row and time limits, and validate it before execution

    Generated queries can be wrong or expensive; least privilege and limits contain the damage.

    Lesson: Design a Text-to-SQL System

  7. Question 7 of 20

    A refund agent can issue refunds. What is a sensible safeguard?

    1. A. Let it refund any amount
    2. B. Require human approval above a set amount or risk level, and make refund actions idempotent
    3. C. Disable logging
    4. D. Retry failed refunds without checks
    View answer

    ✓ B. Require human approval above a set amount or risk level, and make refund actions idempotent

    Money-moving actions need limits, approvals and safe retries so a mistake or retry can't pay twice.

    Lesson: Design a Refund-Handling Agent

  8. Question 8 of 20

    Why would a research agent split work across parallel subagents?

    1. A. To use fewer tokens
    2. B. Each subagent explores one part of the question in its own context, then a lead agent combines the findings
    3. C. Because one agent can't search
    4. D. To avoid writing an answer
    View answer

    ✓ B. Each subagent explores one part of the question in its own context, then a lead agent combines the findings

    Parallel, focused contexts cover broad questions faster, at the cost of more total tokens.

    Lesson: Design a Research Agent

  9. Question 9 of 20

    Code autocomplete must respond in under 200 ms at huge scale. Which choice helps most?

    1. A. The largest available model
    2. B. A small, fast model, plus caching and cancelling stale requests as the user keeps typing
    3. C. Waiting for the user to stop typing for 5 seconds
    4. D. Sending the whole repository every time
    View answer

    ✓ B. A small, fast model, plus caching and cancelling stale requests as the user keeps typing

    Latency is the product here; small models, reuse of context and dropping outdated requests keep it fast.

    Lesson: Design Code Autocomplete

  10. Question 10 of 20

    Many teams share LLMs from several vendors, and customer data mustn't leak. What is the core piece of the platform?

    1. A. Each team calls vendors directly
    2. B. A central gateway that handles access, PII redaction, routing between vendors, quotas and logging
    3. C. One shared API key in a document
    4. D. A single model for everything
    View answer

    ✓ B. A central gateway that handles access, PII redaction, routing between vendors, quotas and logging

    One gateway applies the same safety, cost and audit rules to every call, whichever vendor serves it.

    Lesson: Design a Shared LLM Platform

  11. Question 11 of 20

    For a voice AI agent on a support line, which metric best captures how responsive it feels?

    1. A. Total call length
    2. B. Time from the caller finishing to the agent's first useful words, not filler
    3. C. Words per minute
    4. D. Number of tools available
    View answer

    ✓ B. Time from the caller finishing to the agent's first useful words, not filler

    Filler like 'uh-huh' hides silence without helping; measure the first relevant response, and cut real waits with parallel work and streaming.

    Lesson: Design a Voice AI Agent

  12. Question 12 of 20

    An evaluation gate runs 150 questions on every pull request. What is it good at catching?

    1. A. Every regression, however small
    2. B. Large regressions quickly; small ones need a bigger set before release
    3. C. Nothing, it's too small
    4. D. Only latency changes
    View answer

    ✓ B. Large regressions quickly; small ones need a bigger set before release

    A small set has little statistical power, which is why gates are layered: a fast PR set, a larger release set, and live sampling.

    Lesson: Design an LLM Evaluation Platform

  13. Question 13 of 20

    An invoice extractor is 99% confident about a total that is wrong. What should catch it?

    1. A. Nothing, trust the confidence
    2. B. Business-rule checks that don't depend on the model, such as line items adding up to the total and matching the purchase order
    3. C. A bigger model
    4. D. Re-running the same model
    View answer

    ✓ B. Business-rule checks that don't depend on the model, such as line items adding up to the total and matching the purchase order

    Models can be confidently wrong; independent checks on money fields catch what confidence misses.

    Lesson: Design a Document Extraction Pipeline

  14. Question 14 of 20

    For a coding agent that opens pull requests, which failure is the most serious?

    1. A. The agent fails to open a PR
    2. B. The PR fails CI
    3. C. The PR passes CI but makes the wrong change
    4. D. The PR has a long description
    View answer

    ✓ C. The PR passes CI but makes the wrong change

    A wrong change that passes CI can merge unnoticed and erodes trust in the whole system; verifiers and a scope-checking judge reduce it.

    Lesson: Design a Background Coding Agent

  15. Question 15 of 20

    Why do large platforms moderate chat with many small classifiers instead of one big LLM per message?

    1. A. LLMs can't read chat
    2. B. At hundreds of thousands of messages a second with a millisecond budget, a big LLM is too slow and costly; LLMs are used on the smaller flagged stream
    3. C. Small models are always more accurate
    4. D. Regulations require it
    View answer

    ✓ B. At hundreds of thousands of messages a second with a millisecond budget, a big LLM is too slow and costly; LLMs are used on the smaller flagged stream

    Distilled, quantized specialist models carry the volume; context-aware LLMs and people handle the hard cases.

    Lesson: Design AI Content Moderation

  16. Question 16 of 20

    An AI tutor's users rate it highly. Why isn't that enough to show it works?

    1. A. Ratings are always fake
    2. B. Students may enjoy being given answers; the real test is whether they solve the next problem alone
    3. C. Ratings can't be collected
    4. D. Only teachers can judge
    View answer

    ✓ B. Students may enjoy being given answers; the real test is whether they solve the next problem alone

    Measure learning, such as next-item correctness without help, and track answers given away as a guardrail.

    Lesson: Design an AI Tutor

  17. Question 17 of 20

    LoRA fine-tuning made a small vision model accurate on Indonesian IDs but not on Thai. What's the likely fix?

    1. A. More LoRA epochs
    2. B. Fully train the vision parts on Thai text images (for example synthetic renders), then fine-tune on documents
    3. C. Use a bigger prompt
    4. D. Lower the image resolution
    View answer

    ✓ B. Fully train the vision parts on Thai text images (for example synthetic renders), then fine-tune on documents

    If the vision encoder has rarely seen a script, small adapters can't teach it to read; it needs full training on that script.

    Lesson: Design a Custom Vision LLM

  18. Question 18 of 20

    Fraud is about 1 in 1,000 payments. Why is '99.9% accuracy' a poor way to describe a fraud model?

    1. A. It's too low
    2. B. Approving every payment also scores 99.9%; you need fraud caught and good payments blocked
    3. C. Accuracy can't be computed for payments
    4. D. Fraud models are always 100% accurate
    View answer

    ✓ B. Approving every payment also scores 99.9%; you need fraud caught and good payments blocked

    With rare positives, accuracy hides the trade-off; set thresholds from the cost of each mistake and use verification for the uncertain middle.

    Lesson: Design Real-Time Fraud Detection

  19. Question 19 of 20

    Why do many ETA systems keep the routing engine and train ML to predict its error?

    1. A. Routing engines are always wrong
    2. B. Routing already captures roads and live traffic; learning its error is easier and simpler to update than replacing routing
    3. C. ML can't predict times
    4. D. It removes the need for traffic data
    View answer

    ✓ B. Routing already captures roads and live traffic; learning its error is easier and simpler to update than replacing routing

    The model learns what routing misses, like pickup delays, and an asymmetric loss can penalise lateness more.

    Lesson: Design ETA Prediction

  20. Question 20 of 20

    Why challenge medium-risk sign-ups instead of blocking them?

    1. A. Challenges are free
    2. B. A challenge costs a real person seconds but stops scripts; later layers like cluster detection catch fakes that pass
    3. C. Blocking is illegal
    4. D. Medium risk means no risk
    View answer

    ✓ B. A challenge costs a real person seconds but stops scripts; later layers like cluster detection catch fakes that pass

    A funnel lets each layer be less strict, because the next layer catches what it misses.

    Lesson: Design Spam and Fake Account Detection

MLOps

8 questions on MLOps, from 9 lessons. Pick an answer in your head, then open it.

On the roadmap for: ML Engineering.

  1. Question 1 of 8

    A model looks great offline but fails online. What is training/serving skew?

    1. A. The model is too big
    2. B. Features computed differently in training and in production, so the model sees different inputs
    3. C. Users changed overnight
    4. D. The GPU is slower
    View answer

    ✓ B. Features computed differently in training and in production, so the model sees different inputs

    Computing features once, from shared definitions such as a feature store, keeps them consistent.

    Lesson: Training/Serving Skew and Feature Stores

  2. Question 2 of 8

    When are batch (precomputed) predictions a good fit?

    1. A. When each request needs fresh, per-request context
    2. B. When predictions can be computed ahead of time, such as nightly recommendations for each user
    3. C. Never
    4. D. Only for images
    View answer

    ✓ B. When predictions can be computed ahead of time, such as nightly recommendations for each user

    Batch is cheap and simple; online inference is for decisions that depend on live data.

    Lesson: Batch vs Online vs Streaming Inference

  3. Question 3 of 8

    What is a canary deployment?

    1. A. Running the new model on no traffic
    2. B. Sending a small share of real traffic to the new model and comparing it with the current one before a full rollout
    3. C. Deleting the old model
    4. D. Testing only offline
    View answer

    ✓ B. Sending a small share of real traffic to the new model and comparing it with the current one before a full rollout

    If metrics drop, you roll back with little impact. Shadow mode runs the model without serving its outputs.

    Lesson: Deployment Patterns: Shadow, Canary, A/B and Rollback

  4. Question 4 of 8

    What does a model registry help you do?

    1. A. Train faster
    2. B. Track versioned models with their data, code and metrics, so you can reproduce, promote and roll back
    3. C. Label data
    4. D. Pick hyperparameters
    View answer

    ✓ B. Track versioned models with their data, code and metrics, so you can reproduce, promote and roll back

    Without it, rebuilding last month's model or rolling back quickly is guesswork.

    Lesson: Experiment Tracking, Reproducibility and the Model Registry

  5. Question 5 of 8

    Labels arrive weeks late. What can you monitor today to catch problems?

    1. A. Nothing
    2. B. Input feature drift and changes in the prediction distribution
    3. C. Only the training loss
    4. D. The model file size
    View answer

    ✓ B. Input feature drift and changes in the prediction distribution

    Drift in inputs or outputs is an early warning, although not every drift hurts accuracy.

    Lesson: Drift Detection and Monitoring

  6. Question 6 of 8

    How can you estimate a model's accuracy before any labels arrive?

    1. A. You can't
    2. B. Use its own calibrated confidence scores to estimate expected performance on current data
    3. C. Assume it's unchanged
    4. D. Ask users
    View answer

    ✓ B. Use its own calibrated confidence scores to estimate expected performance on current data

    If probabilities are well calibrated, their average tells you the expected accuracy, a useful early check.

    Lesson: Monitoring Without Labels: Estimating Performance

  7. Question 7 of 8

    What should stop a bad automatic retrain from reaching production?

    1. A. Nothing
    2. B. An evaluation gate: compare the new model with the current one on held-out data, and block it if it's worse
    3. C. Retraining more often
    4. D. A bigger model
    View answer

    ✓ B. An evaluation gate: compare the new model with the current one on held-out data, and block it if it's worse

    Automated retraining needs automated checks, or a data problem ships straight to users.

    Lesson: Retraining Pipelines and Continuous Training

  8. Question 8 of 8

    A recommender retrained weekly on its own clicks keeps showing the same few items. Why?

    1. A. The model is too small
    2. B. It only learns from items it already chose to show (a feedback loop), so other items never get a chance
    3. C. Users dislike variety
    4. D. Clicks are random
    View answer

    ✓ B. It only learns from items it already chose to show (a feedback loop), so other items never get a chance

    Add some exploration or a randomised slice, and correct for exposure, to get unbiased training data.

    Lesson: Feedback Loops and Unbiased Training Data

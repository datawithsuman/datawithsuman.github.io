  1. Question 1 of 12

    Why does an LLM read your prompt quickly but write its answer slowly?

    1. A. The prompt is cached on disk
    2. B. Prefill processes all prompt tokens in parallel (compute-bound), while decode produces one token at a time and is limited by memory bandwidth
    3. C. Output tokens are longer
    4. D. The GPU slows down over time
    View answer

    ✓ B. Prefill processes all prompt tokens in parallel (compute-bound), while decode produces one token at a time and is limited by memory bandwidth

    Each decode step reloads the weights and KV cache for a single token, so memory bandwidth, not FLOPs, sets the speed.

    Lesson: Prefill vs Decode

  2. Question 2 of 12

    Which of these does NOT change the KV-cache size per token?

    1. A. Number of layers
    2. B. Number of KV heads
    3. C. Vocabulary size
    4. D. Bytes per value (e.g. FP16 vs FP8)
    View answer

    ✓ C. Vocabulary size

    Per token the cache is 2 × layers × KV heads × head dimension × bytes. The vocabulary only affects the output layer.

    Lesson: KV Cache Management and PagedAttention

  3. Question 3 of 12

    What problem does PagedAttention solve?

    1. A. Slow tokenisation
    2. B. Wasted KV memory from reserving one large contiguous block per request; fixed-size pages remove most of that waste
    3. C. Low model accuracy
    4. D. Long training time
    View answer

    ✓ B. Wasted KV memory from reserving one large contiguous block per request; fixed-size pages remove most of that waste

    Allocating KV in small blocks on demand, like OS paging, lets far more requests share the GPU.

    Lesson: KV Cache Management and PagedAttention

  4. Question 4 of 12

    Why does 4-bit weight quantization often speed up decoding?

    1. A. It adds more layers
    2. B. Decode is memory-bound, and weights a quarter of the size move through memory faster
    3. C. It removes the KV cache
    4. D. It reduces the vocabulary
    View answer

    ✓ B. Decode is memory-bound, and weights a quarter of the size move through memory faster

    Fewer bytes per weight means less data to read for every generated token, usually with small accuracy loss.

    Lesson: LLM Quantization

  5. Question 5 of 12

    What does continuous batching change compared with static batching?

    1. A. It waits for a full batch before starting
    2. B. Requests join and leave the batch at every decode step, so finished ones don't hold the GPU idle
    3. C. It runs one request at a time
    4. D. It batches only prompts
    View answer

    ✓ B. Requests join and leave the batch at every decode step, so finished ones don't hold the GPU idle

    Scheduling per iteration keeps the GPU busy despite very different output lengths.

    Lesson: Continuous Batching and Scheduling

  6. Question 6 of 12

    A team adds the current timestamp at the start of a long system prompt, and their prompt-cache hit rate drops to almost zero. Why?

    1. A. Timestamps are too long
    2. B. Caching matches an exact token prefix, and a changing first line breaks the match for everything after it
    3. C. Caches expire every second
    4. D. The model rejects timestamps
    View answer

    ✓ B. Caching matches an exact token prefix, and a changing first line breaks the match for everything after it

    Put stable content first and anything that changes, like dates or user data, at the end.

    Lesson: Prefix and Prompt Caching

  7. Question 7 of 12

    How can speculative decoding speed up generation without changing the output distribution?

    1. A. It skips tokens
    2. B. A small draft model proposes several tokens and the big model verifies them in one pass, keeping only accepted ones
    3. C. It lowers the temperature
    4. D. It uses a smaller vocabulary
    View answer

    ✓ B. A small draft model proposes several tokens and the big model verifies them in one pass, keeping only accepted ones

    The acceptance rule guarantees samples follow the target model's distribution; you just get several tokens per big-model pass.

    Lesson: Speculative Decoding

  8. Question 8 of 12

    What does TTFT measure, and which phase mostly sets it?

    1. A. Total tokens per second; decode
    2. B. Time to first token; mostly prefill (plus any queueing)
    3. C. Tokens per user; tokenisation
    4. D. Training time; pretraining
    View answer

    ✓ B. Time to first token; mostly prefill (plus any queueing)

    TTFT covers waiting plus processing the prompt. Time per output token (TPOT) reflects decode.

    Lesson: Serving Metrics and SLOs

  9. Question 9 of 12

    Why does p99 latency shoot up as a server approaches full capacity?

    1. A. The model gets bigger
    2. B. Queueing: as utilisation nears 100%, waiting time grows very fast
    3. C. GPUs cool down
    4. D. Requests get shorter
    View answer

    ✓ B. Queueing: as utilisation nears 100%, waiting time grows very fast

    Near saturation, small bursts create long queues. Plan capacity for latency targets, not peak throughput.

    Lesson: Serving Metrics and SLOs

  10. Question 10 of 12

    A Mixture-of-Experts model activates only a small share of its parameters per token. Why is it still expensive to serve?

    1. A. It needs no GPUs
    2. B. All experts must stay in memory, and tokens routed to different experts need lots of GPU memory and communication
    3. C. Only one user can use it
    4. D. Its outputs are longer
    View answer

    ✓ B. All experts must stay in memory, and tokens routed to different experts need lots of GPU memory and communication

    Compute per token is low, but memory holds the full model, often spread across many GPUs.

    Lesson: Serving Mixture-of-Experts Models

  11. Question 11 of 12

    Reasoning models write thousands of hidden thinking tokens. What does that do to serving?

    1. A. Makes it prefill-heavy
    2. B. Makes it decode-heavy, with longer KV caches and higher cost per answer
    3. C. Removes the KV cache
    4. D. Has no effect
    View answer

    ✓ B. Makes it decode-heavy, with longer KV caches and higher cost per answer

    Those tokens are generated one by one like any output, so latency, memory and cost all rise.

    Lesson: Serving Agents and Reasoning Models

  12. Question 12 of 12

    When is self-hosting an open model usually cheaper per million tokens than an API?

    1. A. Always
    2. B. When you can keep the GPUs busy with high, steady traffic
    3. C. When traffic is tiny and bursty
    4. D. Never
    View answer

    ✓ B. When you can keep the GPUs busy with high, steady traffic

    You pay for GPU hours whether or not they're used, so idle capacity makes each token expensive.

    Lesson: Sizing and Cost: Cost per Million Tokens
